## 1. Summary

AI Success Pte. Ltd. is a Singapore SME financing advisory. It does not lend from
its own balance sheet — it takes one application from a business owner and places
it with the lender on its panel most likely to approve it.

The website exists to convert that positioning into qualified applications. It is
a lead-generation site, not a brochure and not a loan origination system: its job
ends when a business owner's details reach an advisor.

**One-line goal:** turn an SME owner searching for business financing into a
contactable, pre-qualified lead in under five minutes.

---

## 2. Problem

Singapore SME owners looking for financing face a search results page of banks,
licensed moneylenders, and comparison sites that are indistinguishable from one
another. Three things follow:

1. **They cannot tell who will actually approve them.** Most have already been
   declined by at least one bank and do not know whether that outcome generalises.
2. **They cannot compare offers.** Flat rates and effective rates are quoted
   interchangeably, so a "cheaper" quote frequently is not.
3. **They will not fill in a long form on spec.** Any application that demands
   documents before it demands a conversation loses them.

The site has to answer "will you say yes, and what will it cost" convincingly
enough to earn a phone number, without pretending to be a credit decision.

---

## 3. Goals and non-goals

### Goals

| # | Goal |
|---|---|
| G1 | Generate qualified inbound applications from Singapore-registered SMEs |
| G2 | Establish credibility fast enough to survive a first-time visitor's scepticism |
| G3 | Let a visitor self-select the right facility before speaking to anyone |
| G4 | Rank for Singapore SME financing search terms |
| G5 | Give advisors enough context up front to make the first call useful |

### Non-goals

- **Not** a loan origination or underwriting system. No credit decisioning, no
  document upload, no e-signing on this property.
- **Not** a customer portal. No accounts, no repayment tracking, no login.
- **Not** a lender. Nothing on the site may read as a licensed moneylending offer.
- **Not** multi-language at v1. English only.
- **Not** a blog platform. Guides ship as built pages until volume justifies a CMS.

---

## 4. Users

**Primary — the SME owner or director.** Runs a business between roughly S$120k
and S$10m revenue. Time-poor, often browsing on a phone in the evening. Frequently
already declined elsewhere. Wants to know: will I qualify, how much, how fast,
what does it really cost. Low tolerance for jargon and for forms.

**Secondary — the finance manager or controller.** Comparing three or four quotes
on a desktop. Cares about effective rate, fees, early-settlement terms, and
whether a personal guarantee is required. Reads the comparison table and the
glossary; is the reason both exist.

**Internal — the AI Success advisor.** Consumes what the form captures. Every
field on the application form must earn its place by making the first call
materially better, or it should be cut.

## 5. Current state — v1.0 as shipped

Ten static pages, no framework, generated by a small Node layout system so the
header, footer, navigation and icon set are defined once.

| Route | Contents |
|---|---|
| `/` | Hero, five differentiators, product grid, 4-step process, results + stats, testimonials |
| `/loan-solutions` | Product overview, comparison table, eligibility criteria and document list |
| `/working-capital-loan` | Specs, positioning, benefits, worked example, process, 5 FAQs |
| `/business-term-loan` | As above |
| `/invoice-financing` | As above |
| `/equipment-financing` | As above |
| `/why-us` | Positioning, animated stat counters, working process, team |
| `/success-stories` | Four case studies (challenge → facility → outcome) plus six testimonials |
| `/resources` | Six guides, three tools, glossary, 16-question FAQ at `#faq` |
| `/contact` | Application form, repayment estimator at `#calculator`, contact tiles |

**Architecture.** Source in `build/` (`layout.js` + one module per page; the four
product pages share `product.js` and `products-data.js`). `node build.js` writes
the HTML; `npm run build` emits a clean `dist/`. Design system in
`assets/css/styles.css`, interactions in `assets/js/main.js`. Also generated:
`favicon.svg`, `sitemap.xml`, `robots.txt`.

**Delivered as part of v1.0:** responsive from 320px, `prefers-reduced-motion`
respected, all iconography inline SVG (zero image requests), per-page canonical
and Open Graph metadata, JSON-LD for the organisation and each financial product,
`cleanUrls` and baseline security headers via `vercel.json`, and a working
client-side repayment estimator.

**Verified:** no horizontal overflow at 400/500/800/1440px; no broken internal
links; balanced markup on all ten pages; all routes and assets return 200 in
production.

### 5.1 Known defects

| ID | Severity | Defect |
|---|---|---|
| D1 | **Blocker** | The application form has no backend. `main.js` calls `preventDefault()`, shows the success message, and resets — there is no `fetch`, no `action`, no endpoint. **Every submission is silently discarded while the visitor is told an advisor will call.** The site's single conversion action does not work, and it currently makes a false statement to the user. |
| D2 | **High** | Canonical tags, `og:url` and `sitemap.xml` all point at `https://aisuccess.sg`, which does not serve this site. Search engines are being told the canonical version lives at a URL that does not resolve to this content. Either connect the domain or change `SITE.url` in `build/layout.js`. |
| D3 | **High** | All rates, statistics, case studies, the phone number and the UEN are placeholders, on a publicly reachable page for a financial services firm. |
| D4 | Medium | No analytics of any kind. No goal, funnel, or channel in this document can currently be measured. |
| D5 | Low | The Vercel project is not linked to the GitHub repo, so deploys are manual and there is no preview/rollback path. |
| D6 | Medium | The homepage now shows the **real logos** of fifteen financial institutions, sourced from Wikimedia Commons, Wikipedia and the institutions' own sites and self-hosted under `assets/img/logos/`. A trademark notice sits beneath the grid and the caption frames them as *scheme participants*, not AI Success's panel. | D7 | **High** | The government-scheme figures on the homepage — 70% risk-share to March 2027, the Nov 2026 SME Cash Grant, the S$500/S$2,500 amounts — were transcribed from a competitor's page and have not been verified against Enterprise Singapore. Publishing incorrect scheme terms on a financing site is a real liability. Verify before promoting. |

## 6. Requirements

Priority: **P0** blocks a customer-facing launch. **P1** is needed for the site to
do its job. **P2** is the next horizon.

### P0 — blocks launch

| ID | Requirement | Acceptance |
|---|---|---|
| R1 | The application form must deliver submissions to a real destination | A submission produces an email to the advisor inbox **and** a durable stored record. Delivery failure shows the visitor a real error with a phone fallback — never a success message. |
| R2 | The success message must be truthful | Confirmation appears only after the destination confirms receipt. |
| R3 | Spam protection on the form | Bot submissions rejected without a visible challenge for legitimate users (honeypot plus server-side rate limiting; no CAPTCHA unless volume forces it). |
| R4 | Replace all placeholder content with approved figures | Signed off by whoever owns the numbers. Every rate carries its basis (flat vs effective). |
| R5 | Compliance review of all financial claims | Reviewed by a qualified party. Covers the footer regulatory line, "from X% p.a." claims, the estimator disclaimer, and the case studies. |
| R6 | Consent and privacy | Explicit consent language at the point of submission, plus a published privacy policy meeting PDPA obligations. Currently neither exists as a page. |
| R7 | Resolve the canonical/domain mismatch (D2) | Canonicals, `og:url` and sitemap all resolve to the domain actually serving the site. |
| R8 | Case studies and testimonials are real and permissioned | Written consent on file for every named business and individual, or the section is cut. |

### P1 — needed to do the job

| ID | Requirement | Notes |
|---|---|---|
| R9 | Analytics with conversion tracking | Form starts, form completions, calculator usage, per-page entry and exit. Cookie-light and PDPA-compatible. |
| R10 | Lead routing to the advisors' existing workflow | Whether that is a CRM, a shared inbox, or a spreadsheet — decided in §10, Q3. |
| R11 | Click-to-call tracking | Phone is likely a major conversion path; it is currently invisible in the data. |
| R12 | Custom domain with TLS | Plus redirects from the `.vercel.app` hostnames. |
| R13 | Git remote and CI | Push-to-deploy, preview deployments per change, and a rollback path. |
| R14 | Real Open Graph share images | Currently no `og:image`; links shared to WhatsApp — the dominant SG business channel — will render bare. |
| R15 | Performance and accessibility budget | Lighthouse ≥ 95 performance and ≥ 95 accessibility on mobile, enforced per deploy. |
| R16 | Form field review with advisors | Cut any field that does not improve the first call (R-question in §10, Q4). |

### P2 — next horizon

| ID | Requirement |
|---|---|
| R17 | Write the six guide articles. They are currently titled and described but have no destination pages. |
| R18 | Eligibility pre-qualifier — the five-question tool promised on `/resources` and not yet built. |
| R19 | WhatsApp click-to-chat as a first-class entry point. |
| R20 | CMS or structured content source, once someone other than a developer needs to edit copy. |

## 7. Content requirements

The site's credibility rests on it being more straightforward than its
competitors. That is a content constraint before it is a design one.

- **Every rate states its basis.** "From 2.88% p.a." is meaningless without flat
  vs effective. The glossary already makes this argument; the site must not then
  violate it.
- **The estimator is illustrative, and says so** at the point of the number, not
  only in a footnote.
- **No implication of a licensed moneylending offer.** The current footer line
  is a draft, not approved wording.
- **Eligibility criteria must match what the panel actually accepts.** Publishing
  a "6 months trading" floor the lenders will not honour manufactures declines
  and wastes advisor time.
- **Named clients require written consent**, including for the initials-based
  avatars.

---

## 8. Technical constraints

- **Static output, no server-side rendering.** Chosen deliberately: the site is
  ten pages of largely fixed content, and this keeps it fast and cheap. R1 is the
  one requirement that needs server-side execution — a single serverless function
  is the intended scope, not a migration to a framework.
- **Pages are generated, never hand-edited.** Every root `.html` file is build
  output. Edits go to `build/`, then `npm run build`.
- **No runtime dependencies.** The build uses only the Node standard library.
  Keep it that way unless something earns its place.
- **Two external requests only** — the Google Fonts stylesheet and its font
  files. All iconography is inline SVG. Preserve this.
- **Browser support:** current Chrome, Safari, Firefox, Edge, plus iOS and
  Android Safari/Chrome. Mobile is the primary surface.

## 9. Success metrics

Baselines cannot be set until R9 ships; these are the metrics to instrument, with
targets to be agreed once two to four weeks of real data exists.

**Primary**
- Qualified applications per month (qualified = meets published eligibility)
- Visitor → application conversion rate
- Cost per qualified application, by channel

**Secondary**
- Application → advisor contact rate, and time to first contact
- Application → drawdown rate (needs the R10 lead destination to close the loop)
- Phone conversions (needs R11)
- Estimator engagement, and whether it correlates with conversion — it is the
  most expensive interactive element on the site and should justify itself
- Organic sessions on Singapore SME financing terms

**Health**
- Mobile Lighthouse performance and accessibility ≥ 95
- Form delivery success rate — this should be 100% and must be alarmed

## 10. Open questions

These block the P0 work and need answers from the business, not from engineering.

1. **Who owns the numbers?** Someone must sign off the rates, the statistics
   (10,000+ businesses, S$1B+ disbursed, 98% satisfaction) and every case study.
   Until then, D3 stands.
2. **Is `aisuccess.sg` registered and available to point here?** Determines
   whether R7 is a DNS task or a code change.
3. **Where do leads need to land?** Advisor inbox, a CRM, or something else — and
   is there an existing tool the advisors already work from? This defines R1's
   destination and R10 entirely.
4. **What does an advisor actually need before the first call?** The current form
   asks for eight fields. Each one costs completions. Advisors should confirm
   which genuinely improve the call.
5. **Is the panel of lenders nameable?** Naming regulated institutions would be
   the single strongest credibility signal available, and would let the "we say
   yes when banks say no" claim rest on something concrete.
6. **Who is legally responsible for the financial claims?** R5 needs a named
   reviewer, not a process.
7. **Are the four facilities and their published limits accurate** as the actual
   product set, or were they inferred from the mockup?

## Appendix — repository map

```

                         OUT_DIR=dist for a clean deploy bundle

                         and the SITE constants (see D2)
build/pages/*.js         one module per page

                         form handler (see D1), estimator

```

**Commands**

```bash
npm run build       # emit dist/ for deployment
npm run build:root  # build in place, for local preview
npm run dev         # build in place, then serve on :8080
```
